# 开发与维护

## 目录

```text
src/codex_desktop_weixin/   现有运行包名，保留以兼容旧安装
  resident_app.py          独立应用生命周期与单实例
  win_tray.py              Windows 原生托盘
  monitor.py / tailer.py   事件观察与增量游标
  state_machine.py        状态判断；Stop 不单独等同于完成
  notifier.py             持久通知队列和投递
  control_router.py       逐条引用、身份、去重和指令路由
  control_backend.py      指定对话的原生操作
  native_app_tools.py     当前 Desktop 公布的本地工具
  control_contract.py     按实际能力验证，不绑定安装版本
  mobile_copy.py          手机帮助与通知标题文案
tests/                    隔离回归测试
tools/                    安装向导、诊断与发布工具
vendor/cc-connect/        固定基线的适配与精简构建补丁
```

先读根目录的 [长期维护入口](../MAINTENANCE.md)，再按问题查本页。Python 运行部分只使用标准库。小型 C# 启动器通过现有 Explorer 启动 Python，避免继承 Codex 的作业组而随 Desktop 一起退出。

## 消息路径

```text
Codex 本地事件/增量日志 → 状态判断 → 本地通知队列 → CC Connect → QQ
QQ 引用 + 正文 → CC Connect 元信息 → 引用路由 → 当前 Desktop 的原生入口
```

原生接口按实际进程身份和所需方法核对，不根据文件名或安装目录中的版本号猜测。普通发送区分空闲/暂停与忙碌状态；空闲/暂停时通过 Desktop 所有者开始新一轮，运行中普通正文拒绝。Desktop 的 `thread-follower-set-queued-follow-ups-state` 是整份快照替换接口，当前没有可核实的 UI CAS/原子追加能力；不能用进程锁掩盖这个边界，也不能通过隐藏 `codex queue` 绕过。

原生工具连接接受 `codex-app-tools-*` 和旧 `codex-browser-use-*` 名称。缓存只绑定当前 Desktop 进程身份，钩子提示和继承的环境变量都可能过期；失效时按需读取本地管道名称清单，限制候选数量、总时间，并在发送 `tools/list` 前核对实际服务进程。发现只发生在明确调用时，不增加常驻扫描。确认目录后校验所用工具参数，提交前再次核对身份；`tools/call` 一旦开始，任何失败都不能触发换端点重发。显式指定的非法端点不启用自动发现。

引用和入站处理状态保存在本项目自己的数据库；不改写 Codex 历史、认证和账号配置。钩子安装是例外的显式配置动作，只合并自身定义和启用 hooks。

## 测试

```powershell
py -3 -X utf8 -m unittest discover -s tests -v
py -3 -X utf8 tools/check_publication.py
```

隔离测试涵盖状态归并、退出不提醒、错误去重、投递账本、编码、引用、忙时拒绝、接口契约、权限/待办、创建、分支、生命周期和首次配置。真实 QQ 平台和 Codex 模型请求不在单元测试里调用。

Windows 原生测试中有隔离进程、托盘和注册表场景；不要把测试通过当作所有机器、所有 Desktop 版本或 QQ 实收均已验证。CI 检查 Python 3.11/3.13，并在干净环境重新构建固定基线的 QQ 网关。首次安装只使用安装向导及少量就绪检查，不要求用户或安装智能体运行开发测试。新人的首次绑定流程仍需端到端使用反馈。

安装回归分别见 `test_setup_process.py`（含 Windows 真实 Job 进程树、强杀及私有控制台 WM_CLOSE）、`test_setup_recovery.py`（临时目录故障注入）和 `test_setup_diagnostics.py`（真实假构建子进程）。需要只验证启动器构建时运行 `tools/build_resident_app.py --output-dir <隔离临时目录>`，不要覆盖现用 `bin` 或网关。

临时绑定网关在 CreateProcess 时通过 `PROC_THREAD_ATTRIBUTE_JOB_LIST` 原子加入私有 kill-on-close Job；不能改回先 Popen 再 Assign 的有竞态路径。Job 句柄不继承，只有本次日志和空输入句柄传给子进程；不存在 PID 接管或按进程名清理。配置 v2 事务先写校验进度再发布配置，绑定收尾也有写前记录；`--check` 只读验证，持锁的向导才恢复，v1 进度仍可读。散落且无事务归属证据的临时文件不自动删除。

安装钩子只移除本程序自己的处理项，并通过 TOML 解析与语义回读确认：除明确启用 `features.hooks` 外，其他设置保持等价。遇到无法核验的 TOML 布局会拒绝写入。钩子输入有 1 MiB 上限，解码或读取异常会返回安全的继续响应并记录不含正文的诊断。

临时网关的 PID、可执行文件和创建时间在同一 Windows 进程句柄上复核与终止；套接字不可探测时按未知状态保留，不删除路径或结束进程。绑定网关 READY 与正式助手 READY 分开判断；ACP 首条消息的接收边界从已核实的网关就绪时间建立，不能依赖 Python ACP 子进程预热。

监听器先消费转录中的原生事件，再应用迟到钩子。首次回读只跳过目标轮次之前的历史，不能把同一批中后续轮次一并丢弃；游标必须在状态应用成功后提交。清理周期和各目录保留上限集中在 `monitor.py`，不清理未投递记录、活动任务或 Codex 文件。

在其他 Windows 终端宿主实机复核时，用单独的测试机器人和隔离数据目录：分别在等待 READY、等待 OpenID 时点击窗口关闭按钮，再从同一安装目录运行；确认无本次临时进程、旧进度保留且能再次绑定。另测断网、错误密钥、沙箱权限和手机正文实收。自动测试的私有控制台关闭不等于 Windows Terminal、杀毒软件及所有真实 QQ 环境均已验收。

## CC Connect 适配版

基于 v1.5.0 的固定提交，发布适配网关会按 `metadata.patch`、`delivery.patch`、`minimal-build.patch`、`security.patch`、`group.patch` 顺序应用：

1. 原始消息 ID、时间、重连边界和引用信息透传给 ACP。
2. 有路由尾部的引用保存小型持久索引，不只依赖短期内存缓存。
3. 独立提醒走主动发送，不复用旧消息回复上下文。
4. QQ 业务错误、缺少消息 ID 不再当作成功。
5. 精简构建开关同样覆盖上游命令入口，避免未选用的平台/代理被间接导入。
6. 群聊默认关闭；仅接受精确的群/成员白名单，群聊身份查询只回显当前发送者自己的标识，不自动授权；群内权限按钮也绑定同一身份。

配套网关只保留 ACP 和 QQ；校验来源、组件标记及接口，不能只看 `--version`。基线及第三方许可见[声明](../THIRD_PARTY_NOTICES.md)。

普通用户直接运行 `install.cmd`：向导下载本项目 GitHub Releases 的 Windows x64 配套网关，校验发布包、固定二进制哈希和 `BUILD_INFO.json` 中的上游提交。已有且通过校验的网关直接复用；其他版本按下方流程更新。

### 更新已有安装

原地更新 Python 源码通常只需退出助手、更新文件、运行相关回归测试后重新启动，不用重新绑定或安装钩子。`install.cmd` 会识别已有绑定；安装路径或 Python 路径改变属于迁移，不能用首次配置覆盖旧数据。

只有发布版本的网关校验值变化时才需要换网关：

1. 将发布包下载到一个不存在的候选路径；下载器会验证来源、校验值和构建标记，失败时保留现用文件。
2. 退出 **QQ 助手**，不退出 Codex Desktop。确认助手与旧网关退出后，才替换网关；不修改 QQ 配置、OpenID 或 Codex 文件。
3. 留一份临时旧网关供本次失败回退，启动助手后检查 doctor、本地接口与队列。通过后移除临时旧文件，不累积备份。
4. 用 QQ 验证入站和聊天正文实收，不能只凭进程存在或退出码成功宣布完成。

```powershell
# 示例候选路径；不能已经存在，也不能指向现用网关。
py -3 -X utf8 tools/fetch_gateway.py --target vendor/cc-connect/v1.5.0-desktop-control/bin/gateway-update.exe
```

如果移动项目或更换 Python，需要同步核实启动入口、QQ 配置中的绝对路径和钩子命令，并重新信任变化的钩子。不要自动丢弃现有绑定来绕过路径冲突。

### 发布维护

网关发布由 GitHub Actions 的 `ci_build_gateway.py` 管理。流水线核对固定基线、适配补丁、ACP/QQ 测试和组件标记，再打包发布。

更新网关时发布新标签，同时更新下载器中的发布标签和二进制固定校验值。不要改写已发布标签、上传作者运行目录或把本机配置、密钥带入发布包。只有 Python/安装文档改变时无需重复发布同一网关。

## 改文案时

帮助用短段落、换行和少量图标，不依赖 QQ 的 Markdown 渲染。每条分类有独立入口，避免一屏列满内部术语。表情只修饰标题，不改模型正文。

`对话编号：`、`引用标识：`、异步问题尾部是路由契约，不在这些行前后随意插入图标或标点。新通知必须带当前 QQ 作用域的 `引用标识`；旧版纯 `对话编号` 的提醒只在已核实的 `qqbot:<同一 user_id>` 私聊中兼容，群聊或作用域不明时拒绝写操作并引导用户重新发送“对话”选择。新增操作要保留逐条引用、原始时间、身份核对和未知结果不重试，补充测试再写进帮助。

## 发布检查

Git 只跟踪源码、测试、公开文档和补丁。排除个人交接文档、运行配置、日志、历史、二进制及 `app-runtime.json`。发布脚本只能做基础检查，不替代人工检查差异、第三方许可证和新引入依赖。截图请使用虚构示例或获得授权并脱敏。
