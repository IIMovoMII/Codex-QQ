# 智能体安装指南

目标：把用户的 Codex Desktop 接到本人 QQ，不另建 CLI Agent。普通安装只读本页及向导；无需通读开发文档或运行全量测试。已能读取的环境与路径自行核对。

## 执行顺序

1. 复用指定目录，检查来源和已有改动；当前公开源码版在可交互本机终端运行一次 `install.cmd`。向导负责检查、校验下载、续接和启动，不额外串跑 prepare/check；无交互终端时由用户双击同一入口。桌面安装器只有经发布验收后才能替代此入口。
2. **索要凭据前**先讲[没有 QQ 机器人时](install.md#没有-qq-机器人时)的创建、开发设置和测试成员步骤。AppID 是机器人 ID，AppSecret 是密钥，均非 QQ 登录凭据；注册、实名、验证码、平台权限由本人完成。
3. 密钥只在本机隐藏输入，不进聊天、QQ、命令参数或日志。已有有效配置直接复用；首次私聊发送“绑定”，填写机器人返回的 OpenID（不是 QQ 号）并明确确认本人控制权限。
4. 正式助手就绪后按授权合并自身钩子；由用户在 Codex 核对信任。缺项按当前阶段提示，不能声称安装成功即全部可用。
5. 登录自启沿用已有值，新安装默认关闭；本会话已有明确选择就按该选择执行。核对实际系统入口后仍需区分是否经过真实登录验收。

## 续接与异常

| 当前证据 | 处理 |
| --- | --- |
| new | 首次向导；没有机器人先引导创建 |
| preparing / finalizing | 同目录持锁恢复同一事务，不能删除进度重装 |
| pairing | 恢复本次临时网关并等新 READY，再继续 OpenID |
| configured | 复用原绑定进入运行验收，缺失钩子单独处理 |
| conflict / 组件 other-version | 保留原文件，按冲突或组件迁移处理；后者不是 setup_state |
| 环境缺失/错误密钥/平台限制 | 说明具体缺项及下一步；不以旧日志、本地 API 或创建进程冒充 QQ READY |

配置和正式网关分别验证本次 READY。关闭向导须回收本次私有进程树、保存已提交进度；失败按阶段和脱敏日志查，不杀其他网关或删除 pending 文件。

## 数据与权限

数据默认在 `%LOCALAPPDATA%\CodexDesktopWeixin` 和 `%LOCALAPPDATA%\CodexCC`。保留已有身份和数据；群聊默认关闭，只有明确授权才配置精确群/成员白名单，身份查询本身不授权。钩子只合并自身定义与 hooks 开关，其他 TOML 语义不变。

不改 Codex 认证、provider、默认模型、权限、安装包或历史，不结束 Desktop。自定义解释器/CODEX_HOME 须验证 Explorer 与登录启动同样有效。迁移按[开发说明](development.md#更新已有安装)，不以重新绑定解决路径冲突。

## 验收与交付

向导状态不清才补运行 `codex-watch.cmd doctor`。QQ 测试按本会话授权执行：私聊“帮助”“对话” → 引用列表选择专用测试对话 → 引用回执查“设置” → 无害任务 → Desktop 同一对话核对 → QQ 聊天正文核对。结果未知先查，不自动重发；平台消息 ID 不等于实际看见，电脑 QQ 与手机验收也须分别说明。

交付只说明实际入口、托盘退出方式、自启配置与登录验证结果、服务/QQ 测到了哪里及人工待办。故障再查[常见问题](troubleshooting.md)。不附密钥、完整配置或未经验证的能力。
