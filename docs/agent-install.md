# 智能体安装指南

目标：把用户正在使用的 **Codex Desktop** 接到本人 QQ；不要另建 CLI Agent。普通安装只需要本页和安装向导，不必先读完所有文档、研究补丁或运行开发测试。

## 最短执行路径

1. 复用用户指定的项目目录；没有副本时再克隆仓库或下载 ZIP，放到当前用户可写、长期保留的位置。已有副本先检查来源和本地改动，不覆盖用户内容。
2. 在项目根目录的**可交互本机终端**只运行一个入口：

   ```powershell
   .\install.cmd
   ```

   这个向导会自行检查环境、下载并校验网关、准备启动入口、接续已有进度并启动助手。普通安装前不要再分别运行 `--check` 和 `--prepare`；只有用户单独要求只读诊断或只准备文件时才用这两个选项。
3. 让用户只在本机完成需要本人参与的步骤：没有机器人时先创建；输入 AppID 和隐藏的 AppSecret、选择是否使用沙箱；用 QQ 私聊发送「绑定」、填回机器人返回的 OpenID 并明确确认授权。之后由用户确认钩子合并并在 Codex 中信任。**密钥不要经过聊天、命令参数或日志回显。** 已有有效绑定会复用，不重复索取密钥或重新绑定。没有可交互终端时，让用户双击同一个 `install.cmd` 并在本机操作，再继续验收。
4. 向导会核对助手与本地网关就绪；只有向导报告未就绪或状态不清时才额外运行 `codex-watch.cmd doctor`。按下方“验收”区分本机就绪、Codex 信任和 QQ 手机实收。尚待用户操作的项目要明确标记，不声称全链路成功。

能读取的操作系统、Python、路径和安装进度不要问用户；安装向导会检查必要条件并对冲突停止。安装不依赖 GitHub 登录或 Token。

## 按进度处理，不要从头重装

| `setup_state` / 检查结果 | 操作 |
| --- | --- |
| `new` | 向导首次配置；没有机器人时引导用户到 [QQ 开放平台](https://q.qq.com/) 创建 |
| `preparing`、`finalizing` | 配置写入或绑定收尾曾中断；运行同一个 `install.cmd` 校验并接续事务，不新建配置、不删进度 |
| `pairing` | 重新运行 `install.cmd` 接着绑定；不重复索取密钥、不删进度 |
| `configured` | 复用绑定；向导可补齐启动/钩子步骤。版本更新见[更新说明](development.md#更新已有安装) |
| `conflict`、`other-version` | 保留现状，按[排错说明](troubleshooting.md)核实目录或版本，不能清空配置绕过 |
| 依赖缺失 | 说明具体缺项；按用户授权从官方来源安装。不能安装时提供准确的一步人工操作 |
| 非 Windows x64、无交互桌面或 Codex 配置不可解析 | 停在实际缺口，不拿 CLI、另一台机器或空配置冒充成功 |

机器人创建、登录/实名/验证码、平台权限、沙箱成员和钩子信任由用户完成。不要替用户承诺 QQ 一定放行；只给当前一步的提示。是否登录自启由用户在托盘菜单选择，默认关闭。

首次只指导用户在私聊中绑定本人 OpenID。不要让智能体自动打开群聊权限；如果用户明确需要，再说明把机器人加入可信群后在群里使用“群聊身份”命令，并由用户把精确的 `群 OpenID/成员 OpenID` 写入配置。该查询只返回当前群和发送者自己的标识，不会自动授权；群聊对所有成员可见，必须由用户确认可信群。

绑定提示只会出现在本次网关确认 READY 后；创建进程、本地 API 或旧日志都不算 QQ 就绪。关闭向导会清理其私有进程树并保留进度。失败时先读界面给出的阶段、退出码和日志摘要，不能杀其他网关或删除 `setup-pending.json` 来“重试”。

## 路径与安全边界

- 向导默认运行数据：`%LOCALAPPDATA%\CodexDesktopWeixin`；QQ 数据：`%LOCALAPPDATA%\CodexCC`。历史目录名不代表启用微信。不要同时安装两份、不要随意迁移目录。
- 钩子仅在用户确认后合并本程序定义与 `[features] hooks = true`，其他配置保留；已有相同钩子不会重复写入。绑定阶段仅查询本人身份，确认 OpenID 后才启用正式控制，不把首位发送者自动当机主。
- 不改 Codex 认证、provider、模型、权限、安装包或历史；不关闭正在运行的 Desktop。用户需要重启/信任时保存进度，等用户正常操作。
- 默认按 Windows PowerShell 生成钩子。自定义解释器或 `CODEX_HOME` 时先核实整条启动路径；从 Explorer/自启启动也必须指向同一 Codex 配置，不只让当前临时终端可用。
- 程序文件准备失败时，按界面提示的阶段和日志排查，保留发布校验与现用程序。

## 最短验收与交付

运行 `codex-watch.cmd doctor`，核对助手、网关、本地 API 和钩子。向导已启动独立助手后才安装钩子，不用旧的跟随启动命令替代。

用户信任钩子、Codex 有新活动后，手机验收：

1. 发「帮助」「对话」，引用列表选一个测试对话。
2. 引用回执发「设置」，核对项目、标题、模型/档位/权限。
3. 经用户同意发一条无害任务，在 Desktop 确认同一对话与正文。
4. 完成后确认 **QQ 聊天页面里有正文**，不只是通知横幅。

本地 `ready`、平台消息编号和自动测试都不等于手机实收。写操作结果未知时先核对，不自动重发。失败才按需读[常见问题](troubleshooting.md)；开发和全量测试见[开发说明](development.md)。

最后只交付：安装目录、`bin/CodexQQ助手.exe` 开启/托盘退出、自启是否开启、已验证到哪一步、还需用户做什么。不要附密钥或完整配置。
