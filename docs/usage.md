# QQ 操作手册

先在电脑启动助手和 Codex，再在机器人私聊里操作。推荐中文命令：以 `/` 开头的一些命令属于 CC Connect，不一定是本项目的操作。

## 引用就是选择目标

发「对话」看最近 10 个聊天，列表包含项目、标题和状态。引用列表回复序号，会在电脑打开选中的旧对话并返回回执。

之后**每次**都引用这个回执、对应的任务提醒或可操作卡片，再发送正文或命令。旧回执仍可复用，无须总找最新一条。不引用时「设置」「暂停」或普通正文都不会沿用上次选择。

操作卡片的用途不同：列表要回复序号，问题卡片要回答问题，队列回执可查状态/删除。不能把任意卡片都当普通聊天入口；排队回执可引用发「对话」换回目标对话卡片。

## 查找与发送

| 发送内容 | 怎么使用 |
| --- | --- |
| `帮助` | 简短首页，不需要引用；目前仍需要 Desktop 连接可用 |
| `帮助 对话` / `帮助 任务` / `帮助 设置` / `帮助 待办` | 分类用法；引用任意卡片发帮助不会确认或执行卡片操作 |
| `项目` | 列出项目，引用回复序号取得项目卡片 |
| `对话` / `对话 20` | 最近对话，数量 1～50；引用项目卡片时仅看该项目 |
| `搜索 登录` | 按标题查找；引用项目卡片时限定项目 |
| `下一页` | 引用有后续内容的列表查看下一页 |
| 普通正文 / `继续` | 引用目标；空闲或暂停后开始新一轮；运行中进入 Desktop 可见待发送列表 |
| `发送 暂停` | 把“暂停”当普通正文，不执行暂停动作 |

正文上限 4,000 字符。目前只接文本，不把图片、语音或文件当成任务输入。

## 暂停、引导和队列

- `暂停`：停止当前一轮，不是关闭程序；此前已排队消息保留，脱离 Codex 的独立后台程序不保证停止。
- `引导 先检查登录问题`：给执行时正在运行的那一轮补充要求；不锁定先前看到的轮次，没有活动任务就拒绝。
- `队列`：查看当前可核实的 Desktop 可见待发送记录；运行中普通 QQ 消息会进入同一列表，电脑端也能看到。
- 引用旧版发送回执发 `状态`：有证据才报告“正在排队”或“已进入对话”，否则显示未确认。当前忙时普通发送会直接返回 Desktop 可见队列卡片。
- 引用发送回执发 `删除`：只移除仍在排队的这一条；无法撤回已执行的任务。

也可以引用目标对话回执发 `队列`，引用返回列表回复序号，再引用该条卡片发 `删除`。只展示当前能核实的排队记录；列表为空不一定代表 Desktop 的所有队列都为空。

“原生受理”“已经进入对话”“任务完成”“手机实收”是不同阶段。消息记录消失不等于已经开始。没有可靠确认时不会自动重发；也不保证每条排队消息开始时另推一条提醒。

排队消息自动转引导暂不可用。你可以另发「引导 内容」，但这不会删除旧排队消息。

## 模型、思考档位和权限

引用目标对话发送：

| 指令 | 作用 |
| --- | --- |
| `设置` | 查看当前模型、档位、权限、运行状态 |
| `模型` | 列出本机模型目录，引用回复序号 |
| `模型 模型名 档位` | 按名称修改；只接受当前目录确认的模型和档位 |
| `思考档位` / `思考档位 max` | 查看或修改该模型的可用档位 |
| `权限` | 显示权限选项，按卡片要求二次确认 |

QQ 回复沿用这个对话的原生设置，不改成统一默认。设置影响后续轮次，不中途替换正在运行的模型。目录存在某模型不等于当前账号/中转服务一定可调用；不自动降档。权限提高前务必核对目标，自定义原生权限不应被通用选项覆盖。

## 新建、改名、分支和压缩

### 新建对话

引用一个已有对话的回执，发送 `新建对话 检查登录`，按向导选择已有项目或无项目，填写首条任务，再引用确认卡片回复 `确认创建`。

只有最后确认才会创建并执行任务。来源对话只是调用入口，不会收到新任务。模型、档位、权限由原生创建入口解析，可能包含项目默认或来源权限继承；创建后发「设置」核对，不承诺与全局配置或来源对话完全一致。`取消` 会使该向导失效。

### 改名与分支

- `改名 新标题`：修改引用目标的名称。
- `分支`：先查看范围，回复 `确认分支` 执行。只支持空闲、最近一轮已完成且没有自动目标的对话；复制当前完整历史至最近完成位置，原对话不变，新分支不会自动执行任务。
- 暂不支持新建项目、指定更早的分支位置、归档/恢复或编辑历史消息。

### 压缩上下文

发 `压缩上下文`，只在空闲时受理。任务进行中会拒绝，不自动暂停或排队。用 `压缩状态` 查看原生可见记录；由于接口没有独立操作编号，不能保证某条记录严格对应这次 QQ 调用。压缩会调用模型，可能消耗额度或失败。

## 问题、审批与提醒

引用问题提醒发 `待办`，再按具体卡片作答。普通结构化问题、命令审批、文件审批支持的类型可处理，过期或已变化的请求会拒绝；这些路径仍需更多真实设备验收。

异步问题会推送题目和选项，但**请在电脑回答**。登录验证、额外授权和未知请求也留在电脑处理，不能把普通消息或引导冒充审批。

完成、失败、暂停等通知会加一个简短表情区分状态；不会往模型正文里塞表情或改写结论。长内容会裁剪，保留路由尾部。不要编辑、删除引用里的编号/标识，否则无法可靠选中目标。

助手不会因为任务安静很久就推断卡死，也不再发送“Codex 可能异常退出”。应用可独立常驻，但 Codex 未启动或连接失败时新指令直接作废，不在恢复后补执行。
