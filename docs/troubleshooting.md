# 常见问题

桌面应用先打开“帮助与诊断 → 连接诊断”，点击“运行检查”，核对助手、Codex 和 QQ。必要时复制脱敏摘要或保存诊断包。源码安装仍可运行 `.\codex-watch.cmd doctor`。诊断可能含本机路径，分享前自行核对；不要上传 `auth.json`、`cc-connect.toml`、完整日志或聊天记录。

## QQ 没收到提醒

1. 看概览和“QQ 机器人”页是否已连接，在通知记录查看待投递、失败或结果未确认的条目；源码诊断可补看 `cc_connect_api_status` 与 `outbox_pending`。
2. 发「帮助」确认入站；没有回复时检查机器人权限、QQ 身份绑定和网络。
3. 让 Codex 完成一条无害任务，确认 QQ **聊天正文**可见，不能只看手机通知横幅。

历史上曾出现接口成功但正文不可见，原因是独立提醒错误复用了旧被动回复上下文；配套网关补丁把提醒改为主动发送。不要用未打补丁的上游版本替换它。QQ 自身的限制/审核也可能影响投递，不能承诺无限发送或固定条数。

## 群聊没有反应

群聊默认关闭，私聊 `allow_from` 不会自动授权群消息。先确认 QQ 开放平台允许该机器人接收群聊 @ 事件，把机器人加入可信群并在群里 @它发送“群聊身份”。把回执中的 `group_allow_from = "群 OpenID/成员 OpenID"` 写进 QQ 平台配置，保存并重启助手；不要写 `*`、只写成员或只写群号。身份查询只返回当前群和发送者自己的标识，不会自动加入白名单。群聊回复所有成员可见，旧配置或未授权成员不会进入 Codex。

## 无法连接、接口变化、没有窗口所有者

先确认 Codex 已启动，助手和 Codex 由同一普通用户运行。发「对话」并引用序号选择，会尝试载入旧对话，无需预先在电脑点开，也不必先发送一轮任务。等回执显示「已打开并连接」后，引用该卡片发送正文。

Codex 重启或升级后，本地连接地址可能变化。新版会在需要时重新查找当前服务，兼容新旧连接名称，不依赖新对话的钩子刷新地址。桌面应用可在“Codex 连接”重新检查，更新后重启助手；源码原地更新可用 `.\codex-watch.cmd reload-bridge` 加载桥接修复。无需关闭 Codex 或执行模型任务。

若仍不可连接，保留脱敏回执与发生时间并运行连接诊断；也可在电脑打开目标后重新选择。显示「已请求打开，但尚未确认连接」时先等待或核对窗口，再引用卡片；这不代表任务已经发送。

长期对话卡片按其中的 thread ID 定位，不按标题或最近活动猜测。即使本地对话目录暂时没有显示行，引用仍会沿同一个 ID 尝试原生载入；只有原生也无法找到目标时才会拒绝，并保留可继续引用的目标卡片。已经引用目标发送正文时不会重新显示“已选定”卡片；该提示只属于明确的选择操作。

本地记录存在不等于窗口已载入。接口声明变化、原生工具端点不可用和未载入是不同原因，以实际回执为准。程序不锁定 Codex 安装版本，但会验证所需接口；不兼容时更新适配，不要删掉检查或直接修改历史数据库。

长对话的完整 Desktop 状态可能超过 IPC 的 8 MiB 单帧限制。助手会尝试读取同一 thread ID 的最近一轮摘要；若摘要确认对话空闲、最近一轮已结束且恢复完成，普通正文仍可开始新一轮；若摘要确认任务正在运行，普通正文仍可追加到该对话的原生队列。摘要中的可解析异步问题可以只读显示，但不代表已包含全部待办。

答复待办、修改权限、改队列、压缩或分支需要完整原生状态。若回执列出缺少 `requests`、`sandboxPolicy`、`approvalPolicy`、`threadGoal` 等字段，助手不会把它们当作空值，也不会调用依赖这些字段的写接口；请在电脑查看对应的待办/审批/权限或分支前提，再重新查询。回执会分别说明“未调用”或“可能已调用、无确认”；后一种情况先核对实际状态，不要重复执行。长对话提示不代表对话编号改变。

发送回执若显示 Codex 队列命令成功但没有可匹配的队列编号，说明进程退出码成功，但助手无法定位这条具体消息；不能据此说已排队或已开始。不要再次发送相同内容，先检查目标对话的可见待发送列表和最近消息。

已经报“结果未确认”的写指令可能执行过，先到电脑核对，不要连续重发。

## 忙时消息排队与暂停后的消息

任务运行中发送普通正文会通过 `codex queue --thread <对话编号> --message <正文>` 追加到 Codex Desktop 的可见待发送队列；不会替换整份队列，也不会自动变成引导。回执中的队列编号表示 Codex 已受理，不表示已经开始执行。超时或没有精确编号时，结果可能未知，先检查目标对话和可见队列，不要重发。

需要即时补充当前任务时使用「引导 内容」。暂停只停止当前轮次，不会删除已排队消息；后续处理遵循 Codex 队列行为。引用「队列」并选择一条后，回复卡片「引导」会先删除该条，再把原文引导给当前任务；回复「删除」只移除该条。删除和引导是两个操作；若回执显示已删除但引导未接受或结果未知，先检查电脑。

## 任务提醒配置

“Codex 连接”显示实际安装与启用状态；无法核实用户信任时不会提示待确认。只有 Codex 明确要求信任或报告执行失败时，再按其显示处理。桌面应用所需解释器随包安装，可用中文安装器修复缺失资源；源码方式核对 Python 和项目路径，`install-hooks` 只合并本程序定义。

不要把钩子设置为长时间联网发送。它只负责写本地状态；QQ 投递由常驻应用处理。信任被拒绝时不能靠忽略退出码让它“看起来正常”。

## 初次配置中断或报已有配置

桌面应用重新打开后会接续已提交的向导进度；“稍后继续”会停止本次临时连接。源码方式重新运行 `install.cmd`。已保存到有效进度的密钥不需要重输，已有正式绑定直接保留。源码仅准备文件时可运行 `py -3 -X utf8 tools/install_app.py --prepare`，不索取密钥、不启动服务或改钩子。

如果收到“已有安装的路径或模式不同”，优先回到原安装目录更新，不要在第二个目录重新配置。新版会自动核对并接续 `preparing` / `finalizing` 事务；正式配置与进度并存仅在属于同一笔已确认绑定时允许收尾，不会改绑另一人。

配置被手工改动、进度损坏，或旧版本只留下 `cc-connect.toml` 而没有进度时，向导会保留文件并停止。先核对该配置由谁生成、是否仍被现有网关使用；从可信的原进度恢复，或让本地智能体核对身份查询脚本、路径和配置归属后制定定向恢复步骤。没有来源证据时，不自动生成校验记录接管，更不能清空整个应用数据目录或删除 `.codex`。中断在写进度之前留下的 `.setup-*.tmp` 也不自动按文件名批量清理。

临时网关只属于当前安装窗口。窗口关闭、超时、取消或提前退出会清理这棵进程树；如果 Windows 拒绝进程保护或清理，界面会说明对应阶段和错误码，并保留绑定进度。不要按进程名结束所有 CC Connect 实例。

旧版本已经遗留、没有归属记录的网关不会被新版自动接管或结束。如果因此启动冲突，请先核实该进程的可执行路径、命令行和创建时间，确认是旧的临时绑定实例，再由用户定向处理；不要结束现用正式网关。

## 发“绑定”没有回复

先查看向导给出的本机 `logs/setup-gateway.log`：分清机器人认证失败、WebSocket 没就绪、已就绪但没收到私聊事件、事件收到后被过滤，还是 ACP/QQ 回复失败。没有收到事件不能直接证明“QQ 平台拦截”，也不能证明是用户电脑有问题。

向导会等本次连接明确记录 `qqbot: gateway READY` 后再提示发「绑定」。等待上限为 45 秒；日志是追加写入，但旧的 READY 不会被算作本次成功。继承的 `CC_LOG_FILE` 不会把临时网关的日志转走，原日志文件和父进程环境不变。就绪后断网仍可能导致消息失败，需要结合该时间段日志判断。

核对 AppID、AppSecret 所属同一个机器人，沙箱选择与平台实际环境一致，私聊测试权限及测试成员已配置，并通过平台给出的入口联系正确机器人。密钥只在本机核对；分享错误时隐藏凭据、OpenID 和本机路径。

## 不知道怎么创建 QQ 机器人

首次使用向导会在索要凭据前显示平台准备步骤。也可按以下顺序操作：打开 [QQ 开放平台](https://q.qq.com/)并进入控制台 → 创建机器人 → 在“开发设置 / 开发管理”查看 `AppID`、生成或查看 `AppSecret` → 在沙箱、服务范围或测试成员页加入本人 QQ 并开启私信测试 → 回到本机向导输入凭据。两者都不是 QQ 登录密码，平台名称与资格以[官方文档](https://bot.q.qq.com/wiki/)为准。

注册、认证、验证码和测试成员必须由用户在 QQ 页面完成；密钥只在本机密码框填写。暂未准备好可点“稍后继续”；源码安装可按 `Ctrl+C` 后重新运行 `install.cmd` 接续。不要删除 `setup-pending.json` 或清空配置重来。

配套网关已修复 `_meta.cc_connect` 在 ACP 请求边界丢失的问题。请使用安装向导校验的发布版，不要换成未经适配的 CC Connect。

## 找不到 Python / 网关下载失败

桌面安装包自带 Python 和固定网关，无需另外安装 Python 或 Git。缺少或损坏资源时重新运行同版本或新版中文安装器，保留绑定和数据；缺少 WebView2 时需要网络下载微软运行时。

源码安装先运行 `py -3 --version`，需要 Windows x64 Python 3.11+，然后在项目根运行一次 `install.cmd`。单独只读诊断才用 `tools/install_app.py --check`，仅准备文件才用 `--prepare`。下载失败时检查 GitHub Releases 的网络、系统代理、证书及 HTTP 错误，解决后重试并保留校验；不要替换成未经核实的文件。

若提示已有其他版本网关，按[更新已有安装](development.md#更新已有安装)校验候选文件后再换，不清除绑定。

启动入口准备失败时，界面保留退出码和实际错误摘要，完整脱敏输出位于提示的 `logs/setup-*.log`。只有 stderr 的错误、中文和长输出也会保存；日志写入失败会单独说明。

桌面应用通过安装器升级；源码项目或 Python 位置变化时，按[更新已有安装](development.md#更新已有安装)同步入口、QQ 配置和本程序钩子路径，保留已有配置与绑定。

## 自启、托盘与窗口

登录启动直接进入托盘；需要界面时点击托盘图标或开始菜单。若未启动，在“设置 → 通用”重新核对本应用自启和 Windows 启用状态，再区分是否已经过一次真实 Windows 登录。手动运行不算登录验收，也不要同时启动旧源码入口与桌面应用。

窗口位置异常时使用“重置窗口布局”，效果负载较高时可在“设置 → 外观”降低效果质量。1.0.2 已统一缩放时的窗口底色；若拖边框仍出现瞬时黑边，提供应用版本、Windows 版本、主题及缩放比例。

## CPU、内存和退出

桌面应用常驻包括原生宿主、WebView2、本机 Python 服务与精简 CC Connect 网关；入站 ACP 桥可能按会话需要存在。源码方式没有 WebView2 界面，不能直接比较二者内存；也不能按 Node/Python 名称判断进程归属。

应用采用文件事件、增量游标和低频校准，不推测“长时间安静＝卡死”。持续占用高时记录实际可执行路径、PID、时间与负载；先退出本应用再判断，不结束所有 Python/Node 进程或其他插件。

退出助手用托盘菜单，不会关闭 Codex；退出 Codex 后助手仍保留。电脑休眠后不能继续执行，恢复联网也不补发已经作废的入站指令。
