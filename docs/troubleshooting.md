# 常见问题

先运行 `.\codex-watch.cmd doctor`，确认助手、Codex、网关和钩子的状态。诊断可能含本机路径，分享前自行脱敏。不要上传 `auth.json`、`cc-connect.toml`、完整日志或聊天记录。

## QQ 没收到提醒

1. 看托盘是否仍在，`cc_connect_api_status` 是否为 `ready`，`outbox_pending` 是否持续增加。
2. 发「帮助」确认入站；没有回复时检查机器人权限、QQ 身份绑定和网络。
3. 让 Codex 完成一条无害任务，确认 QQ **聊天正文**可见，不能只看手机通知横幅。

历史上曾出现接口成功但正文不可见，原因是独立提醒错误复用了旧被动回复上下文；配套网关补丁把提醒改为主动发送。不要用未打补丁的上游版本替换它。QQ 自身的限制/审核也可能影响投递，不能承诺无限发送或固定条数。

## 群聊没有反应

群聊默认关闭，私聊 `allow_from` 不会自动授权群消息。先确认 QQ 开放平台允许该机器人接收群聊 @ 事件，把机器人加入可信群并在群里 @它发送“群聊身份”。把回执中的 `group_allow_from = "群 OpenID/成员 OpenID"` 写进 QQ 平台配置，保存并重启助手；不要写 `*`、只写成员或只写群号。身份查询只返回当前群和发送者自己的标识，不会自动加入白名单。群聊回复所有成员可见，旧配置或未授权成员不会进入 Codex。

## 无法连接、接口变化、没有窗口所有者

先确认 Codex 已启动，助手和 Codex 由同一普通用户运行。发「对话」并引用序号选择，会尝试载入旧对话，无需预先在电脑点开，也不必先发送一轮任务。等回执显示「已打开并连接」后，引用该卡片发送正文。

Codex 重启或升级后，本地连接地址可能变化。新版会在需要时重新查找当前服务，兼容新旧连接名称，不依赖新对话的钩子刷新地址。更新旧版助手后，只需在项目目录运行 `.\codex-watch.cmd reload-bridge` 加载桥接修复；它不关闭 Codex，也不执行模型任务。

若仍不可连接，保留完整回执及发生时间，运行 doctor 检查；也可在电脑打开目标后重新选择。显示「已请求打开，但尚未确认连接」时先等待或核对窗口，再引用卡片；这不代表任务已经发送。

本地记录存在不等于窗口已载入。接口声明变化、原生工具端点不可用和未载入是不同原因，以实际回执为准。程序不锁定 Codex 安装版本，但会验证所需接口；不兼容时更新适配，不要删掉检查或直接修改历史数据库。

已经报“结果未确认”的写指令可能执行过，先到电脑核对，不要连续重发。

## 暂停后消息还在队列

新的普通发送会在确认空闲/暂停后开始一轮；运行中会追加到 Desktop 可见待发送列表。以前已经排队的消息不会被自动清理。引用「队列」并选择一条后，回复卡片「引导」会先删除该条，再把原文引导给当前任务；回复「删除」只移除该条。旧版发送回执支持查看状态或删除，不支持直接转换。删除和引导不是原子操作；若 QQ 提示已删除但引导未接受或结果未知，先检查电脑，不要盲目重发。

## 钩子未信任或失败

核对 Python 仍在、项目路径没有改变、当前命令解释器是否支持生成的调用命令。`install-hooks` 会合并定义，需要在 Codex 核对并信任；源码原地更新通常不改变钩子命令。

不要把钩子设置为长时间联网发送。它只负责写本地状态；QQ 投递由常驻应用处理。信任被拒绝时不能靠忽略退出码让它“看起来正常”。

## 初次配置中断或报已有配置

重新运行 `install.cmd`。向导会接续待绑定进度，已保存到有效进度的密钥不需要重输；已有正式绑定会直接保留。只需准备文件时，智能体可运行 `py -3 -X utf8 tools/install_app.py --prepare`，不索取密钥、不启动服务或改钩子。

如果收到“已有安装的路径或模式不同”，优先回到原安装目录更新，不要在第二个目录重新配置。新版会自动核对并接续 `preparing` / `finalizing` 事务；正式配置与进度并存仅在属于同一笔已确认绑定时允许收尾，不会改绑另一人。

配置被手工改动、进度损坏，或旧版本只留下 `cc-connect.toml` 而没有进度时，向导会保留文件并停止。先核对该配置由谁生成、是否仍被现有网关使用；从可信的原进度恢复，或让本地智能体核对身份查询脚本、路径和配置归属后制定定向恢复步骤。没有来源证据时，不自动生成校验记录接管，更不能清空整个应用数据目录或删除 `.codex`。中断在写进度之前留下的 `.setup-*.tmp` 也不自动按文件名批量清理。

临时网关只属于当前安装窗口。窗口关闭、超时、取消或提前退出会清理这棵进程树；如果 Windows 拒绝进程保护或清理，界面会说明对应阶段和错误码，并保留绑定进度。不要按进程名结束所有 CC Connect 实例。

旧版本已经遗留、没有归属记录的网关不会被新版自动接管或结束。如果因此启动冲突，请先核实该进程的可执行路径、命令行和创建时间，确认是旧的临时绑定实例，再由用户定向处理；不要结束现用正式网关。

## 发“绑定”没有回复

先查看向导给出的本机 `logs/setup-gateway.log`：分清机器人认证失败、WebSocket 没就绪、已就绪但没收到私聊事件、事件收到后被过滤，还是 ACP/QQ 回复失败。没有收到事件不能直接证明“QQ 平台拦截”，也不能证明是用户电脑有问题。

向导会等本次连接明确记录 `qqbot: gateway READY` 后再提示发「绑定」。等待上限为 45 秒；日志是追加写入，但旧的 READY 不会被算作本次成功。继承的 `CC_LOG_FILE` 不会把临时网关的日志转走，原日志文件和父进程环境不变。就绪后断网仍可能导致消息失败，需要结合该时间段日志判断。

核对 AppID、AppSecret 所属同一个机器人，沙箱选择与平台实际环境一致，私聊测试权限及测试成员已配置，并通过平台给出的入口联系正确机器人。密钥只在本机核对；分享错误时隐藏凭据、OpenID 和本机路径。

配套网关已修复 `_meta.cc_connect` 在 ACP 请求边界丢失的问题。请使用安装向导校验的发布版，不要换成未经适配的 CC Connect。

## 找不到 Python / 网关下载失败

先运行 `py -3 --version`；没有 Python 时安装 Windows x64 的 Python 3.11+，关闭并重开终端。没有 Git 可在 GitHub 点击 Code → Download ZIP，解压后运行 `install.cmd`。

智能体只需运行 `py -3 -X utf8 tools/install_app.py --check` 查看简短状态，再执行 `--prepare` 准备程序。下载失败时检查到 GitHub Releases 的网络、代理、证书及 HTTP 错误；解决后重试，保留文件校验和现用版本。

若提示已有其他版本网关，按[更新已有安装](development.md#更新已有安装)校验候选文件后再换，不清除绑定。

启动入口准备失败时，界面保留退出码和实际错误摘要，完整脱敏输出位于提示的 `logs/setup-*.log`。只有 stderr 的错误、中文和长输出也会保存；日志写入失败会单独说明。

项目目录或 Python 位置变化后，需要重新准备启动入口、更新 QQ 配置中的路径，并重新安装/信任路径变化后的钩子。迁移时保留已有配置和绑定。

## CPU、内存和退出

正常常驻是助手进程与精简 CC Connect 网关；入站 ACP 桥可能按会话需要存在，具体进程数不能只凭 Node/控制台进程名称判断。其他插件的进程不一定属于本项目。

本机曾短采样到助手＋网关约 53 MiB 工作集、全机 CPU 低于 0.1%；这只是特定机器短采样，不是性能保证。应用采用文件事件、增量游标和低频校准，不推测“长时间安静＝卡死”。如果持续占用高，记录明确的可执行文件路径、PID、时间及负载，而不是结束所有 Python/Node 进程。

退出助手用托盘菜单，不会关闭 Codex；退出 Codex 后助手仍保留。电脑休眠后不能继续执行，恢复联网也不补发已经作废的入站指令。
